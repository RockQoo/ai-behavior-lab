# 설계

## 질문

보스 패턴이 파악되면 숙련자가 파훼법을 만들고, 그 뒤로는 공략이 고정된다. **보스가 공략에 적응하면 이 고착을 늦추거나 막을 수 있을까?**

목표는 강한 보스가 아니라 **읽을 수는 있지만 외워서 끝낼 수는 없는 보스**다.

- 모든 공격에 예고가 있고, 사람 수준으로 반응하면 피할 수 있다.
- 보스는 입력을 몰래 읽지 않는다. 보이는 행동만 보고 판단한다.
- 적응은 플레이어가 알아챌 수 있어야 한다.
- 적응 강도에는 상한을 둬서 이길 수 있는 상태를 유지한다.

## 구조

```
[시뮬레이션 코어]  CombatSimulation, 고정 틱, 결정적
   │  Observation: 자기 상태(정확) + 상대 상태(반응 지연·오차 적용)
   ▼
[IBrain]  FSM / BT / GOAP / HTN / 유틸리티, 또는 조합
   │  Intent: 이동(방향) 또는 행동(ActionId, 방향)
   ▼
[행동 상태 머신]  RunningAction: 선딜 → 판정 → 후딜, 스태미나·회복약 검사
   ▼
[시뮬레이션 코어]
```

- 모든 Brain은 같은 인터페이스(관찰 → 의도)를 가진다. 봇마다 다른 Brain을 끼워 대결시킨다.
- Brain은 게임 상태를 직접 바꾸지 못하고 의도만 낸다. 어떤 기법이든 같은 규칙과 같은 한계 안에서 싸운다.
- 행동 상태 머신은 게임 규칙이다. 판단용 FSM Brain과는 별개다.

### 한 틱의 순서

1. 양쪽 Brain이 같은 시점의 관찰로 의도를 정한다.
2. 의도를 적용한다(행동 시작 또는 이동). 조작 실수는 여기서 생긴다.
3. 행동을 한 틱 진행한다(이동형 이동, 회복, 무적 여부, 단계 전환).
4. 판정한다. 양쪽 판정은 같은 틱에 함께 처리한다.
5. 몸 겹침 밀어내기, 경기장 경계, 스태미나 회복.
6. 지금 상태를 관찰 기록(반응 지연용)에 넣고 승패를 확인한다.

### 결정성

- 난수는 `DeterministicRandom`(SplitMix64)만 쓴다. `System.Random`, 시간, 해시 순서에 기대지 않는다.
- 난수 흐름을 용도별로 나눈다(관찰 오차, 조작 실수, Brain마다). 한 쪽 사용량이 바뀌어도 다른 쪽이 흔들리지 않는다.
- 같은 PC, 같은 빌드에서 같은 시드면 같은 결과. 다른 CPU 간 부동소수점 일치는 목표가 아니다.

### 화면과의 분리

- `AiBehaviorLab.Core`는 화면을 모른다. Godot 4 C#에서 참조할 수 있게 `net8.0`으로 둔다.
- 수만 판은 콘솔에서 돌리고, 보고 싶은 판만 Godot에서 재생한다. 재생 속도(느리게, 한 틱씩)는 결과에 영향이 없다.

## 의사결정 기법을 섞는 방법

| 층 | 질문 | 잘 맞는 기법 |
|---|---|---|
| 전략 | 이번 전투를 어떻게 풀까 | HTN, GOAP |
| 선택 | 지금 무엇을 할까 | 유틸리티 AI |
| 실행 | 고른 것을 어떤 순서로 할까 | BT |
| 단순 반응 | 상태에 따라 바로 바꾸기 | FSM |

기법별 진화 대상:

| 기법 | 진화시키는 것 |
|---|---|
| FSM | 전이 조건 문턱값 |
| BT | 자식 노드 순서, 조건값 |
| GOAP | 행동 비용 |
| HTN | 메서드 우선순위, 조건 |
| 유틸리티 | 점수 곡선 가중치 |

## 리플레이

두 방식 중 **상태 기록**을 쓴다.

| | 입력 리플레이 | 상태 기록 (채택) |
|---|---|---|
| 저장 | 시드 + Brain 설정 | 매 틱 상태(위치, HP, 행동, 범위 모양, 사건) |
| 재생 | 다시 시뮬레이션 | 기록을 그리기만 |
| 결정성 | 기계·런타임 사이에서도 필요 | 필요 없음 |

- 고정소수점은 쓰지 않는다. 필요한 경우는 다른 기계 사이의 입력 리플레이·락스텝인데, 이 프로젝트는 해당하지 않는다.
- 위험 지점: `Sin`, `Cos`, `Acos`, `Asin`은 런타임·CPU마다 결과가 다를 수 있다. 러너(.NET 10)와 Godot(.NET 8 계열)이 다르다.
- 그래서 프레임마다 상태 해시(FNV-1a, 실수는 비트 그대로)를 저장하고, 다른 런타임에서 다시 돌려 비교할 수 있게 했다.
  2026-11-20 확인: 러너가 기록한 시드 7(1,863프레임)을 Godot 안에서 다시 돌려 모두 일치.
- 한 판 약 1MB(62초 기준). 보고 싶은 판만 기록한다.

## 관전 화면 (2단계)

- 도형: 보스 큰 원, 플레이어 작은 원, 바라보는 방향 삼각형
- 머리 위: HP, 지금 하는 행동, 남은 시간
- 바닥: 노란색 = 예고, 빨간색 = 판정 순간
- 오른쪽 패널: 판단 근거(후보 행동 점수), 보스가 파악한 플레이어 습관
- 재생: 0.25배, 일시정지, 한 틱씩, 되감기, 타임라인
